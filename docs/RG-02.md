# RG-02 — Google y sincronización cifrada

**Estado inicial:** RG-01 integrada en main, CI verde. RG-02 en rama aislada, sin Release publicada.

## Decisiones de seguridad

- Una sola identidad de Firebase Authentication: **UID**, no correo electrónico ni nombre.
- Firestore almacena únicamente bytes RG01 cifrados (AES-256-GCM) de entradas y de la DEK envuelta. El texto de las entradas no se utiliza como ID ni como campo de consulta.
- La DEK de RG-01 se mantiene; nunca se transmite la KEK local no exportable de Android Keystore.
- La recuperación usa un código generado por SecureRandom de **160 bits** (32 caracteres Base32, agrupados). Este código se muestra únicamente al propietario para custodia fuera de Firebase; no se envía al servidor y no puede regenerarse a partir de Google.
- El código deriva una clave independiente separada por propósito y UID. Un AES-GCM distinto envuelve la DEK con AAD asociada al UID. La clave se borra del array temporal al terminar.
- La restauración en otro dispositivo DEBE requerir autorización de Google, código de recuperación y autenticación local con PIN/biometría para vincular la DEK al Keystore del nuevo dispositivo.
- Sin cuenta o sin red, los datos locales permanecen cifrados y utilizables. Los cambios locales nunca se descartan por fallar la nube.
- Fusión de tres vías: baseline cifrada, local y remota. Cambios independientes se combinan, conflictos sobre el mismo elemento se bloquean sin sobrescritura silenciosa; eliminar frente a editar también es conflicto.
- Todas las escrituras deben validar la revisión en una transacción remota antes de reemplazar un snapshot. No usar un 'set' ciego; tampoco guardar un snapshot local vacío sobre una cuenta que ya tiene bóveda.
- Reglas Firestore **cerradas por defecto** hasta introducir explícitamente el UID autorizado. No publicar reglas de 'todos los usuarios autenticados'.
- La cuenta Google comprometida NO equivale a descifrado sin el código de recuperación. La pérdida de Google **y** del código y de todos los dispositivos con sesión local funcional hace la recuperación imposible: avisar en la UI.

## Subfases

1. **RG-02-P01:** primitivas de recuperación y fusión con pruebas unitarias, documentación del modelo de amenazas.
2. **RG-02-P02:** integración Credential Manager + Firebase Authentication, configurada sin credenciales reales en el repo.
3. **RG-02-P03:** backend Firestore, baseline cifrada local, operación offline y transacciones CAS.
4. **RG-02-P04:** flujos UI de alta y recuperación, batería de pruebas CI, simulaciones de conflicto y verificación de contrato RS-05.

## Restricciones RG-01/RS-05

No cambiar package ID, certificate, canal de publicación ni formato de la bóveda local. Sin APK Debug/diagnóstico para el propietario. CI con Release sin firmar; pruebas de firma/dispositivo previstas en RG-04.
