# RG-04 — Release oficial, despliegue progresivo y certificación Android

**Fecha:** 11/11/2026. **Estado:** validación física principal del Realme superada; P05 pendiente de tablet y pruebas negativas reales. RG-03 integrada en PR #4, candidata 0.2.0 fusionada en PR #7.
**Dispositivos:** Realme GT Neo 2 disponible; Galaxy Tab S9+ para validación posterior.
**Protocolo obligatorio:** RobPublisher → RS-05 → GitHub Release → RobStore; sin APK Debug ni publicación manual.

## Principios y límites

- Identidad Android `es.robertodorado.robguard`, firma Release original, configuración de Firebase y datos persistentes inmutables durante esta fase.
- El CI compila `testReleaseUnitTest`, `lintRelease`, `assembleRelease` y comprueba RS-05 SIN generar una Release distribuida.
- La existencia de una compilación Release sin firma en CI NO equivale a verificar la firma privada de producción, Secrets ni una instalación real.
- Las reglas definitivas RG-03 fueron publicadas en Firebase Console según confirmación del propietario y contrastadas con sincronización real exitosa del Realme autorizado. No se ha ejecutado aún una prueba directa real de denegación de Google UID y UID revocado.
- El modo RG-03 estuvo desactivado en Release 0.1.0 y se activó en la 0.2.0 oficial publicada y actualizada sin borrar datos.
- Hasta validar restauración y redundancia, utilizar exclusivamente contraseñas ficticias; no almacenar secretos reales como única copia.

**Puerta P01:** PR #4 fusionada; PR de preparación RG-04 validada; ninguna Release, migración ni alteración de firma/secretos.

## P03 — Validación física inicial RG-01/RG-02 en Realme

1. Con entradas FICTICIAS: crear, consultar, modificar, copiar, buscar, generar y borrar elementos de la bóveda.
2. Verificar biometría/bloqueo Android, bloqueo por inactividad, `FLAG_SECURE` de la bóveda abierta, funcionamiento offline, reinicio y persistencia.
3. Verificar Google propietario, sincronización cifrada RG-02, código de recuperación copiado a un lugar externo seguro, y manejo seguro de pérdida de conexión y conflictos.
4. No reinstalar, borrar datos, cambiar claves ni depender de una sola copia real si aparece un fallo. Registrar incidencias y corregirlas en nuevas Releases firmadas, incrementando `versionCode` en cada nueva publicación.

**Puerta P03:** RG-01/RG-02 operativas en un Android físico con Release oficial, sin pérdida de datos. Las pruebas de segundo dispositivo siguen pendientes.

## P04 — Migración controlada a reglas RG-03

Ejecutar **solo después de superar P03**, siguiendo al detalle `docs/RG-03-MIGRACION.md`.

1. Guardar externamente el código de recuperación; habilitar Firebase Auth Anonymous y comprobar la configuración de limpieza de cuentas.
2. Desplegar temporalmente `firestore.rg03.preparation.rules`; durante esta ventana la revocación por dispositivo NO es eficaz.
3. En nueva versión Release con `rg03_device_access_enabled=true`, `versionCode` incrementado y publicación mediante RobPublisher, registrar el Realme como `pending`.
4. Autorizar el primer dispositivo manualmente en Firebase Console, modificando únicamente los campos indicados en la guía. Verificar inventario y sincronización.
5. Desplegar las reglas FINALES `firestore.rg03.rules`; probar denegación a Google UID heredado y a instalaciones pendientes/revocadas, y acceso a la instalación autorizada.
6. No dejar las reglas temporales en producción ni declarar revocación segura mientras siga existiendo la ruta antigua.

**Puerta P04:** la bóveda solo admite UIDs anónimos de instalaciones autorizadas; la sesión Google propietaria ya no concede acceso directo a /vaults.

**Puerta RG-04:** RobGuard instalada y actualizable desde RobStore, RG-01/02 probadas físicamente, RG-03 con reglas finales y revocación verificada en dos instalaciones. Sin tablet, la fase queda parcialmente certificada.

## Registro de dependencias no verificables desde código

- No inferir el estado real de la configuración privada de GitHub Actions, la presencia de secretos, el topic del repositorio o la clave de firma por el simple resultado del CI.
- No afirmar que `firestore.rules` del repositorio refleja necesariamente las reglas vigentes de Firebase Console hasta comprobar el despliegue.
- No confundir Android CI verde, ejecución del motor de firma y prueba física: son puertas distintas.
